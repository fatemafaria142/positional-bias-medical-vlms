# Rotated Samples — Positional-Bias Rotation Probe

Rotated copies of `samples/amos22_mri/` and `samples/neurite_oasis/`, generated by
`scripts/rotate_samples.py`, for testing whether a model's segmentation follows the
requested structure's actual content/position or is instead biased toward a fixed
array location regardless of what's really there.

## What was done

Each subject's image + label volume was rotated **180 degrees about its own
Superior/Inferior axis** (read per-volume from its NIfTI affine, never assumed —
same convention as `scripts/common3d.py`). Concretely:

- Left <-> Right and Anterior <-> Posterior are swapped in the array; Superior/Inferior
  is unchanged.
- This is a **proper rotation** (determinant +1) — physically the same as the patient
  being spun 180 degrees on the table — not a mirror/flip, so the anatomy stays valid
  (a "left kidney" is still a real left kidney, just relocated in the array).
- The rotation is exact on the voxel grid (`numpy.flip` along the two non-S/I axes,
  no interpolation), so image and label masks stay pixel-perfect aligned.
- Ground truth (`gt_centroid_vox_*`, `gt_bbox_vox_*`, `gt_side_axis*`) is fully
  recomputed against the rotated array and its correctly-updated affine, not copied —
  so `gt_side_axis*` still reports the *true* anatomical side (a right kidney is still
  labeled `R`), even though its voxel position moved. Verified: on `amos_0544`, `right
  kidney`'s centroid moves from voxel `(389, 175, 28)` to `(186, 292, 28)` (axis 0/1
  flip to `575-x`, axis 2 unchanged) while `gt_side_axis0` stays `R`.

## Why this is useful for a positional-bias probe

Run the exact same prompt ("Segment the right kidney in this image.") against both
the original and the rotated volume. A model that segments based on real image content
should find the right kidney in its new (rotated) voxel location. A model with
positional bias — e.g. one that has learned "the right kidney is usually near array
index X" — will instead predict a mask near the *old* location, which now contains a
different (or no) structure. Comparing Dice / centroid error between the original run
and the rotated run isolates that failure mode directly.

## Using it in the existing VoxTell notebooks

No code changes needed beyond the dataset path — the manifest column names, subject
IDs, organ names, and prompts are all identical to the un-rotated samples. In
`voxtell-amos-kaggle.ipynb` / `voxtell-amos-kaggle-v2.ipynb`:

```python
AMOS_DIR = RESEARCH_REPO / 'samples' / 'sample_rotation' / 'amos22_mri'
```

And in `voxtell-oasis-kaggle.ipynb`:

```python
OASIS_DIR = RESEARCH_REPO / 'samples' / 'sample_rotation' / 'neurite_oasis'
```

Run once against `samples/amos22_mri` / `samples/neurite_oasis` (original) and once
against `samples/sample_rotation/amos22_mri` / `samples/sample_rotation/neurite_oasis`
(rotated), then compare the two prediction CSVs.

## Regenerating

```bash
python scripts/rotate_samples.py
```

Reads the manifests and volumes already committed under `samples/amos22_mri/` and
`samples/neurite_oasis/` — no download needed — and (re)writes everything under
`samples/sample_rotation/`.
