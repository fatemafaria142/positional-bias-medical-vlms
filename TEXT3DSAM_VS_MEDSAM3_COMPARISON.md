# Text3DSAM vs. Medical SAM3 - Paper Comparison

Sources:
- Text3DSAM: [arxiv.org/abs/2604.24876](https://arxiv.org/abs/2604.24876) (Xin et al., 2025) - note this arXiv ID is the one that also carries the ESICA paper's own listing; the OpenReview link originally supplied (`openreview.net/pdf?id=egbzGkOWVf`) is behind a Cloudflare browser check that automated fetching could not pass, so the numbers below come from the arXiv version and from the ESICA paper's own baseline comparison tables, not the OpenReview PDF directly. Worth a manual check if you need OpenReview-specific text (e.g. reviewer discussion).
- Medical SAM3 (confirmed as the model actually run in this repo): [arxiv.org/abs/2601.10880](https://arxiv.org/abs/2601.10880), "Medical SAM3: A Foundation Model for Universal Prompt-Driven Medical Image Segmentation" (Jiang, Ding, Song, et al.; corresponding authors Yu Tian, Ziyang Yan). Code: [github.com/AIM-Research-Lab/Medical-SAM3](https://github.com/AIM-Research-Lab/Medical-SAM3). Checkpoint used in this repo: `ChongCong/Medical-SAM3` on Hugging Face.

**Note on an earlier mix-up:** a different, similarly-named paper - "MedSAM-3: Delving into Segment Anything with Medical Concepts" ([arxiv.org/abs/2511.19046](https://arxiv.org/abs/2511.19046), Liu et al., code at `github.com/Joey-S-Liu/MedSAM3`) - was mistakenly used for this comparison in an earlier draft. That is a separate, unrelated project (2D-only, LoRA fine-tuning, COCO/YOLO-format tooling) and is **not** the model used in this repo. It's mentioned here only so the two don't get confused again if either name resurfaces.

**External confirmation of the naming collision:** an ECCV 2026 paper, "From Reasoning to Pixels: Grounded Medical Multimodal LLMs for VQA and Segmentation" (MedREAL, Gu et al.) - [PDF](https://media.eventhosts.cc/Conferences/ECCV2026/pdfs/12494.pdf) - independently cites both "MedSAM3" papers as two separate references in its related work (see `CVPR_ECCV_2024_2026_SEGMENTATION_VLM_PAPERS.md`), which is outside confirmation that these really are two distinct works and not a mislabeling on this repo's part.

## Comparison table

| Field | Text3DSAM | Medical SAM3 |
|---|---|---|
| **Full name** | Text3DSAM | Medical SAM3: A Foundation Model for Universal Prompt-Driven Medical Image Segmentation |
| **Authors** | Xin et al. | Jiang, Ding, Song, et al. (corresponding: Yu Tian, Ziyang Yan) |
| **Base model / backbone** | SAM-style promptable segmentation paradigm, adapted to text-guided 3D volumetric segmentation | Full fine-tuning of SAM3 (all layers updated, no LoRA/adapter) - authors state full-parameter fine-tuning "strengthens medical domain visual priors" more than partial approaches |
| **Text encoder** | `nlpie/tiny-clinicalbert` (small, distilled BERT variant) | Not a separate encoder; inherits SAM3's own text/concept pathway, fine-tuned end-to-end |
| **Parameter count** | 59.30 M | Not stated as a total; it's SAM3 at full scale, fully fine-tuned, so its size follows SAM3's own parameter count |
| **Compute (FLOPs)** | 24.55 G (smallest of the methods it was benchmarked against) | Not stated; training used 4x NVIDIA H100 (80GB) GPUs, training resolution 1008x1008, up to 10 epochs |
| **Native dimensionality** | 3D only (whole volume in, whole mask volume out) | 2D-centric by design - even for volumetric data it processes each slice as a high-fidelity 2D image rather than natively 3D, a deliberate choice the authors say "maximizes applicability across diverse workflows without constraints from inconsistent 3D geometries" |
| **Prompt types accepted** | Text only (one plain organ/structure phrase per call) | Text only at training and inference - the paper explicitly removes reliance on ground-truth bounding boxes/points, forcing the model to learn spatial grounding from language alone |
| **Task framing** | Promptable 3D segmentation: text names one class, model returns one binary mask volume for that class | Text-driven semantic alignment + set-prediction objective (Hungarian matching, instance discovery and semantic segmentation combined); multi-class scenarios handled by querying each class independently, resolved via pixel-wise maximal confidence |
| **Training data** | [CVPR-BiomedSegFM](https://huggingface.co/datasets/junma/CVPR-BiomedSegFM), ~200,000 3D image-mask pairs assembled from public biomedical datasets for the CVPR 2025 text-guided segmentation challenge | 33 datasets, 76,956 images, 263,705 mask annotations, across 10 modalities (radiography/X-ray/angiography ~40,160 images, ultrasound ~12,179, endoscopy/fetoscopy ~12,887, plus pathology, fundus/OCT, dermoscopy, microscopy, virtual microscope, electron microscopy, and others); 85/15 train/val split (~65.4k training images) |
| **Modalities covered by training data** | CT, MR, PET, ultrasound, and microscopy (CT-dominant: the largest single-modality share in CVPR-BiomedSegFM is CT) | Radiography, ultrasound, endoscopy/fetoscopy, pathology, fundus/OCT, dermoscopy, microscopy, virtual microscopy, electron microscopy (10 modalities total) - notably no MRI-of-brain or dedicated abdominal-MRI dataset called out |
| **AMOS22 MRI in training data?** | Not directly. AMOS is present in CVPR-BiomedSegFM only via its **CT arm** (`CT_AMOS`) - the MRI arm used in this repo's evaluation is a different, unseen modality for the same anatomy | **No.** None of the 33 training datasets or 10 training modalities include abdominal MRI at all (its modality list has no MRI entry of any kind) |
| **Neurite OASIS in training data?** | **No.** CVPR-BiomedSegFM's class taxonomy has zero neuroanatomical/brain-structure classes (no hippocampus, amygdala, thalamus, ventricles, cortex, etc.), and the OASIS skull-stripped/template-aligned preprocessing style is unlike anything in its CT/MR/PET/ultrasound/microscopy training mix | **No.** Same absence - no brain-MRI data, no neuroanatomical classes, and no template-aligned/skull-stripped preprocessing style anywhere in its 10 training modalities |
| **Zero-shot vs. fine-tuned in this repo's use** | Run zero-shot in this repo (no fine-tuning here) against AMOS22 MRI and Neurite OASIS, both **fully out-of-distribution** relative to its own CVPR-BiomedSegFM training set | Run zero-shot in this repo against the same AMOS22 MRI and Neurite OASIS volumes, both **fully out-of-distribution** relative to its own 33-dataset training set |
| **Benchmark used in the paper** | CVPR-BiomedSegFM held-out validation split (in-distribution for the model, since it's the same benchmark it was trained/tuned on) | Internal validation: 10 held-out splits from its own 33-dataset pool (in-distribution). External validation: 7 fully unseen datasets (out-of-distribution test, not used in training at all) |
| **Headline reported score (paper's own benchmark)** | DSC 0.6091, NSD 0.6161, F1 0.1138, DSC-TP 0.2434 (overall, across all CVPR-BiomedSegFM modalities) | Internal validation: mean Dice 77.0% / mean IoU 67.3% (vs. base SAM3's 54.0% / 43.3%, a +23.0 pt Dice gain from fine-tuning). External (unseen) validation: mean Dice 73.9% / mean IoU 64.4% (vs. base SAM3's 11.9% / 8.0%, a +62.0 pt Dice gain) |
| **Modality breakdown (paper's own benchmark)** | CT: DSC 0.6707 / NSD 0.6095. MRI: DSC 0.5214 / NSD 0.5920. Ultrasound: DSC 0.8337 / NSD 0.8117 | Notable per-dataset swings cited in the paper: PS-FH-AOP'23 fetal ultrasound 65.7% to 91.6% Dice after fine-tuning; DRIVE retinal vessels 24.8% to 55.8%; GlaS'15 glands 68.9% to 88.2%; endoscopic polyp sets CVC-ClinicDB and ETIS-LaribPolypDB both went from 0.0% (base SAM3 fails completely) to 87.9% and 86.1% respectively |
| **This repo's own zero-shot result** | AMOS22 MRI mean Dice 0.1025 (liver best ~0.26); Neurite OASIS mean Dice 0.000 (0/350 nonzero) - see `TEXT3DSAM_RESULTS_ANALYSIS.md` | Run in this repo following the same organ/structure-prompt pipeline as Text3DSAM, against both AMOS22 MRI and Neurite OASIS; predictions written to `predictions_medsam3_<dataset>.csv` and figures under `results_medsam3_amos/`, `results_medsam3_oasis/` (partial results present in-repo; check those CSVs directly for the current mean Dice, since I have not re-scored them for this document) |
| **Agentic / reasoning layer** | None - a single forward pass per (volume, text) pair, no iterative refinement | None - a single highest-confidence mask returned per text prompt, no MLLM-driven refinement loop |
| **Compared against, in its own paper** | ESICA, ESICA-Lite, CAT, SAT (all on CVPR-BiomedSegFM) - Text3DSAM is the smallest and cheapest of the group but scores lowest on DSC/NSD/F1/DSC-TP among them | Primarily its own base model, SAM3 (pre- vs. post-fine-tuning). Mentions MedSAM, Medical SAM Adapter, SAM-Med3D, MedSAM2, nnU-Net, UniSeg/MedUniSeg, and SAT as related work, but does not report direct numerical comparisons against them in its result tables |
| **License** | Not stated in the sources gathered here (verify on the HF checkpoint page, `MagicXin/Text3DSAM`) | Not confirmed in the excerpts retrieved; check the GitHub repo/HF checkpoint page directly |
| **Stated limitations** | Not stated explicitly in the excerpts retrieved; the ESICA paper's own comparison frames Text3DSAM as the cheapest but weakest-accuracy baseline in its class | (1) Full-parameter fine-tuning at high resolution is computationally demanding, parameter-efficient strategies flagged as future work. ## Prompt design used in this repo, and whether it's correct

- **What's used:** `--prompt "1={organ}"`, where `{organ}` is the plain AMOS/OASIS organ or structure name straight from the manifest (e.g. "liver", "right kidney", "left hippocampus"), one class queried per call, `--instance` mode for a clean binary mask with no cross-class argmax competition.
- **Why it matches the paper:** Medical SAM3's own training used "only text prompts paired with ground-truth segmentation masks, without any spatial or interactive prompts such as points or bounding boxes," with prompts "derived directly from the dataset's clinical labels" mapped to "a unified vocabulary of canonical concept names." At inference, the paper describes multi-class scenarios as querying "each class independently" and resolving overlaps "via pixel-wise maximal confidence" - exactly the one-organ-per-call, `--instance` pattern this repo uses. So the prompting *approach* is correct for this model.
- **Caveat worth checking:** the paper's exact canonical-vocabulary term list isn't published. Multi-word AMOS/OASIS names like "inferior vena cava," "right adrenal gland," or "left ventral DC" are plausible canonical terms, but if the model's training vocabulary used different phrasing or an abbreviation for any of them, that specific organ's score could reflect a vocabulary mismatch rather than a true segmentation failure - worth a spot-check on the weakest-scoring organs if the repo/checkpoint ships its own label list.
- **Bigger caveat, from this paper's own stated limitations:** Medical SAM3 is fundamentally a **2D-slice model** applied to 3D volumes, and its authors themselves flag this as a limitation ("planar representation may underutilize native volumetric continuity; native 3D prompting recommended"). Whatever pipeline feeds AMOS22 MRI / Neurite OASIS volumes into it (slice-by-slice inference, then reassembled into a 3D mask) is working against the grain of how the model was designed to be extended to volumes, unlike Text3DSAM which is natively 3D end-to-end. This is a modeling-fit difference worth calling out in any write-up, separate from whether the prompt wording itself is correct.
- **Neither dataset's modality is in-distribution for either model.** Text3DSAM's training set has no brain-MRI or dedicated abdominal-MRI data (AMOS is present only via its CT arm); Medical SAM3's 10 training modalities list has no MRI at all. Both models are being evaluated fully zero-shot and out-of-domain on AMOS22 MRI and Neurite OASIS, which is useful context for interpreting low scores from either one.

## Reading notes for building your own table

- **Different benchmarks, not directly comparable head-to-head.** Text3DSAM's 0.609 DSC and Medical SAM3's 73.9%-77.0% Dice are each measured on that paper's *own* benchmark, not the same test set - a side-by-side number in one table can look like a direct competition, but it isn't one.
- **Text3DSAM is 3D-only and single-modality-per-call**, purpose-built for volumetric CT/MR/PET/ultrasound/microscopy text-to-mask prediction, whereas **Medical SAM3 is 2D-slice-native and multi-modality broad** (10 modalities, mostly non-MRI) - the two aren't solving quite the same problem despite both being "text-promptable medical segmentation" at a glance.
- Text3DSAM's parameter count (59.30 M) and FLOPs (24.55 G) come from its listing as a baseline inside the ESICA paper's own comparison table, not a self-reported number inside a Text3DSAM-authored table - worth citing that provenance if this table goes into a paper draft.
- I could not verify the Text3DSAM OpenReview PDF directly (Cloudflare browser check blocked automated fetch both via the PDF link and the JSON API). If your table needs OpenReview-specific claims (e.g. reviewer scores, a different abstract wording, or supplementary material only on OpenReview), that page needs a manual open in a real browser.

## A third model worth adding: VoxTell (CVPR 2026)

[VoxTell: Free-Text Promptable Universal 3D Medical Image Segmentation](https://openaccess.thecvf.com/content/CVPR2026/papers/Rokuss_VoxTell_Free-Text_Promptable_Universal_3D_Medical_Image_Segmentation_CVPR_2026_paper.pdf) (Rokuss et al., CVPR 2026) is the closest published relative to Text3DSAM found in a broader CVPR/ECCV 2025-2026 search (see `CVPR_ECCV_2025_2026_SEGMENTATION_VLM_PAPERS.md`): it's also a free-text-promptable, natively 3D, universal medical segmenter, trained on 62K+ CT/MRI/PET volumes across 1,000+ anatomical/pathological classes, and reported as state-of-the-art on the **same CVPR-BiomedSegFM benchmark** Text3DSAM uses. Since it shares Text3DSAM's exact benchmark (unlike Medical SAM3, whose benchmark is entirely different), VoxTell is a more apples-to-apples comparison point than Medical SAM3 is, if you want a same-benchmark baseline row. It has not been run in this repo, so no local zero-shot numbers exist for it yet - only its own paper's reported scores are available.
