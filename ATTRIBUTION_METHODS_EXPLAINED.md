# LIME vs SHAP vs Exact Shapley in the VoxTell study

| | **Exact Shapley (reference method)** | **SHAP / KernelSHAP (verification method)** | **LIME (baseline method)** |
|---|---|---|---|
| **Research question** | Does VoxTell use the side word ("left"/"right") or only the organ name? This method answers it by measuring how much each word contributes to the Dice score. | Does VoxTell use the side word ("left"/"right") or only the organ name? This method answers it by measuring how much each word contributes to the Dice score. | Does VoxTell use the side word ("left"/"right") or only the organ name? This method answers it by measuring how much each word contributes to the Dice score. |
| **One-line idea** | Split the credit for the score fairly between the side word and the organ word. | Compute the same fair split, but through a regression, using the standard `shap` library. | Fit a small linear model around this one prompt and read the weight of the word. |
| **Origin** | Game theory (Shapley, 1953). | Lundberg and Lee (2017). | Ribeiro, Singh and Guestrin (2016). |
| **Why we use it** | • Accuracy alone cannot show whether the side word matters, because a model that ignores it can still score well when the organ is easy to find.<br>• Shapley is the only attribution that divides credit fairly (efficiency, symmetry, dummy player, additivity), so it gives the most defensible answer to the side-grounding question. | • A hand-written Shapley implementation can contain mistakes, and nothing in the code proves it is correct on its own.<br>• SHAP is a published, widely used library that computes the same quantity by a different route. If it returns the same numbers, the Shapley code is verified.<br>• It also shows the practical route for longer prompts, where exact enumeration is too costly. | • LIME is the most commonly used text explainer, so leaving it out would raise the question of why.<br>• It rests on a different principle: a local linear surrogate instead of fair credit division.<br>• Comparing it against Shapley shows whether the popular shortcut reaches the same conclusion. If it does not, that is itself a finding. |
| **What would be missing without it** | There would be no principled answer to whether the model is grounded on side. | There would be no independent evidence that the Shapley numbers are correct. | There would be no comparison with the method most people would have used. |
| **Reasoning** | Each role is a player and the Dice score is the payout. The credit of a role is its average marginal contribution over every order in which the roles could be added. | Attribution is written as a baseline value plus a weighted sum of role indicators. Shapley values are the only solution that is locally accurate, consistent and respects missing features. | An input is complicated globally but roughly linear in its neighbourhood. Perturb the input, watch the model, and fit a weighted line. |
| **Players** | • Two roles: position (side word) and organ.<br>• Function words such as "the", "in" and "image" always stay in the prompt. | • Two roles: position (side word) and organ.<br>• Function words such as "the", "in" and "image" always stay in the prompt. | • One word at a time: either the position word or the organ word.<br>• Function words stay in the prompt. |
| **What is perturbed** | • The side word and the organ word are each present or absent, which gives 4 prompts per organ.<br>• An absent role is replaced by a neutral filler or a landmark phrase, so the prompt stays grammatical. | • The side word and the organ word are each present or absent, which gives 4 prompts per organ.<br>• An absent role is replaced by a neutral filler or a landmark phrase, so the prompt stays grammatical.<br>• The 4 prompts are read from the cache that exact Shapley already filled. | • The full prompt is compared with the prompt where the word is ablated.<br>• LIME's own sampling decides whether the word is kept or dropped in each trial. |
| **Metric equations** | f_dice_gt = 2 × |P ∩ G| / (|P| + |G|)<br>f_dice_self = 2 × |P ∩ B| / (|P| + |B|)<br>f_centroid_shift = centroid_RL(P) − centroid_RL(B)<br>f_volume = |P| − |B|<br>P = predicted mask for the prompt, G = ground-truth mask, B = mask for the full prompt | f_dice_gt = 2 × |P ∩ G| / (|P| + |G|)<br>f_dice_self = 2 × |P ∩ B| / (|P| + |B|)<br>f_centroid_shift = centroid_RL(P) − centroid_RL(B)<br>f_volume = |P| − |B|<br>P = predicted mask for the prompt, G = ground-truth mask, B = mask for the full prompt | Only f_dice_gt is used, passed as the pair [1 − Dice, Dice]. |
| **Calculation** | φ_i = Σ over S ⊆ N∖{i} of [ |S|! (n − |S| − 1)! / n! ] × ( v(S ∪ {i}) − v(S) ) | φ = argmin Σ k(z') × ( v(h(z')) − φ_0 − Σ φ_i z'_i )², with k(z') = (n − 1) / ( C(n, |z'|) × |z'| × (n − |z'|) ) | ξ(x) = argmin over g of Σ π_x(z) × ( f(z) − g(z') )² + Ω(g) |
| **Model runs** | 4 per organ, cached. | 0 extra, because it reuses the cache. | 10 (the number of samples), although only 2 distinct prompts exist per word. |
| **Repeatable** | Yes, always. | Yes, when every combination is enumerated. | No. The result depends on the random seed and the number of samples. |
| **Guarantee** | Efficiency: the position credit plus the organ credit equals the full-prompt score minus the empty-prompt score. | • Efficiency, as for exact Shapley.<br>• When every combination is enumerated, it equals exact Shapley (stored per row as `matches_exact_shapley`). | None. It is only a local approximation. |
| **Strength** | Fair, exact and unambiguous. | Checked against a trusted library. | Fast, familiar and easy to explain. |
| **Limitation** | The cost grows as 2 to the power of the number of roles, so it cannot handle full-sentence attribution. | It is only partly scalable, and with two roles it adds no new information. | • Its perturbations differ from the role ablations.<br>• With 2 prompt variants per word, it is close to a single comparison of "with the word" against "without the word". |
| **How to read the result** | • Position credit large and positive: the model is grounded on side.<br>• Position credit near zero while the organ credit holds the whole score: the positional-bias signature.<br>• Position credit negative: the side word pushes the mask away from the ground truth. | • Agreement with exact Shapley confirms the implementation is correct.<br>• Disagreement would point to a bug. | • A sign or size different from the Shapley credit is a finding: random word deletion can mislead on this task.<br>• It is reported and not tuned away. |
| **Role in the paper** | Step 1: answers the research question. | Step 2: confirms the answer was computed correctly. | Step 3: compares the answer against the popular baseline. |
| **Code** | `shapley_values(v, roles)` | `shap.KernelExplainer` | `lime.lime_text.LimeTextExplainer` |
| **Output file and column** | `word_attribution_<suffix>.csv`, column `shapley_value` | `shap_attribution_<suffix>.csv`, column `shap_value` | `lime_attribution_<suffix>.csv`, column `lime_weight` |

**Notes**
- With two roles, exact Shapley is simple arithmetic. SHAP and LIME add credibility and a baseline, not new information.
- The LIME result is thin (2 prompt variants per word, 10 samples), so it should be treated as a baseline and not as evidence.
